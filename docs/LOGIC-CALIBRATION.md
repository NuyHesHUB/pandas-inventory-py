# FIFO 로직 교정 기록 (Logic Calibration)

도구가 만든 결과물과 **사람이 직접 만든 실제 결과물**을 대조해서, 미세하게 어긋나는
품목을 찾아 로직을 지속적으로 교정하기 위한 문서다.

운영 방식: 사람이 결과물을 만들 때마다 도구 출력과 비교 → 어긋난 품목을 아래
"사례 기록"에 남김 → 원인을 분류 → 수정 시 **반드시 회귀 테스트를 함께 추가** →
수정 이력에 기록.

## 현재 로직 요약

기간 판매량과 cutoff 시점 종료재고를 더해 최근 입고부터 역산(scope)한 뒤,
그 범위의 가장 오래된 lot부터 판매량을 FIFO 배분한다 (`fifo_for_product`).

### 입고 제외 휴리스틱 (원화/국내/반품 제외)

| 조건 | 판정 | 위치 |
|---|---|---|
조건은 **두 가지**다. 공급처 상호로 판정하지 않는다.

| 조건 | 판정 | 위치 |
|---|---|---|
| 공급처/매출처/비고에 "반품"·"return" 포함 | 제외 | `__is_return__` |
| 단가 ≥ 500, 또는 단가·공급처 셀 서식이 ₩/원/KRW | 원화(국내 매입)로 간주, 제외 | `__is_high_krw_unit_price__` (← `__is_krw_accounting_format__` 포함) |

**국내 매입은 입고(수입)단가 열의 ₩500 이상으로만 판별한다.** 2026년 시트 전수
조사에서 단가 셀 서식과 값이 정확히 갈린다.

| 단가 셀 서식 | < 500 | ≥ 500 |
|---|---|---|
| `"₩"#,##0` | 0 | 235 |
| `\$#,##0.00` 계열 | 336 | 0 |
| `[$¥-804]#,##0.00` 계열(엔화) | 33 | 0 |

₩ 서식인 행은 전부 500 이상이고 500 이상인 행은 전부 ₩ 서식이다. 달러·엔화 행은
하나도 500을 넘지 않으므로 이 임계값에서 외화가 오발될 여지가 없다.

2026-10-27 이전에는 **공급처 상호에 한글이 있으면 국내 매입**으로 보는 조건이
하나 더 있었는데, "화동"·"Hefei Top Industry(무역회사)" 같은 한글 상호 수입처의
입고를 통째로 떨어뜨려 폐기했다 (아래 수정 이력 참조).

⚠️ 남은 오발 여지: "반품 아님" 같은 메모, 복사-붙여넣기로 묻거나 빠진 ₩ 서식.
오발 사례가 나오면 여기 기록할 것.

### 날짜 3원화 — 행마다 세 가지 날짜가 다른 용도로 쓰인다

| 용도 | 기준 |
|---|---|
| 판매 집계 | 날짜 우선, 없으면 도착일 (`__event_date__`) |
| 입고 lot | **도착일 우선**, 없으면 날짜 (`__in_date__`) |
| 재고 스냅샷 | 날짜만 (`__row_date__`) |

## 보류 중인 결정 (규칙 미정 — 사용자 확인 대기)

### 1. 단가 칸이 빈 국내 매입 행을 어떻게 할 것인가

국내 매입 판별은 `단가 ≥ 500(₩)`인데, **단가 칸 자체가 비면 이 규칙이 걸 수 없다.**
2026년 시트 기준 단가 빈 입고행 845건 중 776건은 `"₩"#,##0` 서식이 남아 있어
`__is_krw_accounting_format__`이 잡지만, `$` 서식이 잘못 묻은 69건이 통과한다
(예: `선록`·`ZnO(P)-2호`는 대부분 행이 ₩ 서식인데 한두 행만 `\$#,##0.000`).

2026/09/23~10/26 기준 영향:

| 처리 방식 | 데이터 행 | 단가·환율 빈 행 | 제외 품목 |
|---|---|---|---|
| 현행 (그대로 둠) | 204 | **79** (45개 품목) | 17 |
| 단가 빈칸도 제외 | 128 | 0 | 59 |

선택지: ① 단가가 비면 제외 ② 그대로 두고 사람이 채움 ③ 원장에서 69건 서식을
₩로 교정(코드 수정 없이 ①과 같은 결과).

### 2. BHT(재고)에 2022년 lot이 붙는 것이 맞는가

`BHT(재고)`는 최근 매입이 전부 원화(제너럴케미칼, 4,300원)라 제외되는데, 역산
범위를 채우지 못해 2022년까지 거슬러 올라가 **2026년 10월 원가에 2022-04-04
lot(3.83 / 1233.2)** 을 붙인다. `BHT(중국산)-25KG`도 같은 경로로 2022-12-12
lot(4.85 / 1286.2)을 쓴다. 합계는 맞으므로 티가 나지 않는다.
→ 사람이 만든 결과물의 해당 품목과 대조 필요. 아래 용의자 1·3번과 같은 뿌리다.

## 남은 용의자 (미확정 — 사례가 나오면 대조할 것)

1. **경계일 날짜 불일치**: 운송 중 입고(날짜 ≤ cutoff < 도착일)는 lot에서 빠지는데
   현재고에는 반영돼 있으면 부족분이 생겨 보정 seed가 발동 → 오래된 단가가 끼어듦.
   *시그니처: 월말/월초 경계에 입고가 걸친 품목에서 뜬금없는 옛 입고일 lot.*
2. **제외 휴리스틱 오발**: 위 표의 2개 조건 참조.
   *시그니처: 특정 입고 건 하나가 배분에서 통째로 빠짐.*
3. **보정 seed의 은폐**: 역산 범위가 lot 합계로 안 채워지면 부족분을 가장 오래된
   유가 lot에 붙인다. 합계는 항상 맞으므로 다른 원인을 가린다. `[결과] ... 합계=X |
   기대값=X` 로그는 검증 근거가 되지 못한다.
   *시그니처: 가장 오래된 입고일에 비정상적으로 큰 배분량.*
4. **과거 연도 역추적에 깊이 제한이 없음**: `_load_inbound_events_progressive`는
   수량이 찰 때까지 연도를 계속 거슬러 올라간다 (2021년까지). 최근 매입이 전부
   원화로 제외되는 품목은 구조적으로 이 길로 빠진다.
   *시그니처: 기간과 몇 년 차이 나는 입고일 lot.* (보류 중인 결정 2번 참조)
5. **품명 표기 변형**: 소스 내 변형은 서로 다른 품목으로 집계됨 (템플릿↔소스 매핑만
   canon 비교, 소스끼리는 미통합). 2026년 실존 4그룹:
   `CG 560`/`CG-560`(둘 다 수입 — lot이 쪼개짐), `PVC EL 103K`/`PVC EL103K`,
   `PEG 4000`/`PEG-4000`, `ZnO 180`/`Zno 180`(대소문자만 다름).
   *시그니처: 판매량 자체가 눈에 띄게 부족.* → 원장에서 통일하는 게 가장 빠르다.
6. **연도 경계**: 전년 12월 이력이 새해 시트에 "12월 30일"로 적히면 당해 12월로
   파싱됨. *시그니처: 연초 기간에서 기초재고성 lot 누락.*
7. **단가 결측 보정**: 단가 빈 lot에 같은 품목의 직전 유효 단가를 끌어다 쓴다
   (`_impute_alloc_pricing_from_inbound`). 2026년 기준 환율 있는 입고 358행 중
   5행이 해당(전부 0.1~3kg 샘플). 결과물에 실제 값과 구분 없이 찍힌다.
8. **₩ 서식 판정 대상에 공급처 칸이 포함됨**: `krw_format_cols`에 단가 열뿐 아니라
   공급처 열이 들어간다. 텍스트 칸에 묻은 회계 서식으로 원화 판정이 바뀐다.
9. **반품 판정이 부분 문자열**: 공급처·매출처·비고 중 하나라도 "반품"/"return"을
   포함하면 제외. 비고는 자유 서술이라 "반품 아님" 같은 메모도 걸린다.
10. **숫자 정제 정규식**: `_to_num_frame`이 `[^\d\.\-]`를 지우므로 `"1-2"` → `-12`,
    `"약 3"` → `3`처럼 조용히 통과한다.
11. **시트 선택이 단순 문자열 포함**: `[s for s in wb.sheetnames if str(year) in s]`.
    `2026년 세율` 같은 시트가 추가되면 조용히 합쳐진다.
12. **읽는 컬럼 폭 128 고정**: 서식 흔적으로 `max_column`이 수천까지 뜨는 걸 막는
    성능 장치인데, 실제 데이터가 128열을 넘으면 조용히 잘린다.
13. **수동 별칭 하드코딩**: `_build_alias_map`에 `MOCA(China)→MOCA` 등 5건 +
    강제 미매핑 1건이 코드에 박혀 있다. 근거가 코드에 없고 품명이 늘 때마다 수정 필요.
14. **템플릿 anchor의 "수기 흔적" 정의**: 비표준 수식이거나 단가가 텍스트일 때만
    사람이 확정한 배분으로 본다. 표준 수식 그대로 수량만 고쳤으면 덮어쓴다.

## 불일치 리포트 절차

어긋난 품목을 발견하면 아래 순서로 확인하고 사례 기록에 남긴다.

1. **기본 정보**: 품목명, 대상 기간, 도구 출력 lot(입고일/단가/환율/수량) vs
   사람 결과물 lot.
2. **원장에서 확인할 것** (위 용의자와 대응):
   - [ ] cutoff 직전 행의 現재고 칸이 비어 있거나 텍스트인가?
   - [ ] 같은 날짜에 입고/거래 행이 여러 건인가?
   - [ ] 어긋난 lot 행의 날짜와 도착일이 cutoff를 사이에 두고 갈리는가?
   - [ ] 단가가 ≥ 500(₩)이거나, 단가 칸이 비었거나, 비고에 "반품" 문자열이 있는가?
   - [ ] 원장에 같은 품목의 표기 변형(공백 차이 등)이 있는가?
3. **분류 후 수정**: 원인이 특정되면 수정하고, 해당 사례를 재현하는 단위 테스트를
   `tests/`에 추가한 뒤 위 "수정 이력" 표를 갱신한다.
